# v0.1.0 設計書: ELF ローダーとプロセス実行

## 概要

ELF64 バイナリをRamFS上からロードし、カーネル空間で実行する基盤を構築する。
完全なRing3遷移はv0.2.0に延期し、まずカーネルスレッドとしてのELF実行を目標とする。

## 前提

- GDT: USER_CS(0x18), USER_DS(0x20), TSS(0x28) スロット定義済み（TSS未初期化）
- context.cm: init_task() でカーネルスレッド生成可能
- Process struct: pid, state, context, kernel_stack, page_table, brk_addr
- RamFS: ファイル読み書き可能、最大4KiB

## Phase A: ELF64 パーサ + exec コマンド

### 新規ファイル

| ファイル | 内容 |
|---------|------|
| `exec/elf.cm` | ElfHeader/ProgramHeader パーサ |
| `exec/loader.cm` | ELFファイルをメモリにロードしプロセス生成 |

### ELF64ヘッダ構造

```
// e_ident[16] + e_type(2) + e_machine(2) + e_version(4) +
// e_entry(8) + e_phoff(8) + e_shoff(8) + e_flags(4) +
// e_ehsize(2) + e_phentsize(2) + e_phnum(2) + ...
// 合計 64バイト
```

### ロードフロー

1. RamFS からELFファイルを読み込み
2. ELFヘッダを検証（マジックナンバー 0x7F454C46）
3. PHDRを走査し、PT_LOAD セグメントをメモリにコピー
4. e_entry (エントリポイント) をカーネルスレッドとして実行
5. ProcessTable + Scheduler に登録

### exec シェルコマンド

```
exec <filename>  — RamFS上のELFを実行
```

## Phase B: TSS初期化（準備のみ）

- TSS構造体を固定メモリに配置
- RSP0（カーネルスタック）を設定
- GDTのTSSスロットにTSSアドレスを書き込み
- ltr (Load Task Register) を実行

> Ring3遷移は v0.2.0 で iretq を使用して実装予定

## 制約

- ELFファイルサイズ: RamFS制限 (4KiB) 内
- 実行はカーネル権限 (Ring 0) のまま
- PIE/共有ライブラリ未対応（静的リンクELFのみ）
- セクションヘッダ解析なし（プログラムヘッダのみ）
