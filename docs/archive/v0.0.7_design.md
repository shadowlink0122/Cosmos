# v0.0.7 設計書: ページフォルト対応と仮想メモリ拡張

## 概要

ページフォルトハンドラにDemand Paging対応を追加し、
mmap/brk syscall でユーザー空間のメモリ管理基盤を実装する。

## 前提

- PageTable struct: map_page/unmap_page/translate 実装済み
- BuddyAllocator: alloc_pages/free_pages 実装済み
- page_fault.cm: CR2取得+パニック（Demand Paging未実装）
- PMMポインタ: 0x95010 (SHELL_PMM_ADDR) に格納

## 新規ファイル

| ファイル | 内容 |
|---------|------|
| `mm/mmap.cm` | Mmap struct — 仮想メモリ領域管理(VMA) |

## 既存ファイル変更

| ファイル | 変更内容 |
|---------|---------|
| `mm/page_fault.cm` | Demand Paging: 非存在ページフォルト時にVMA確認→マッピング |

## VMA (Virtual Memory Area) 設計

```
struct Vma {
    ulong start;    // 開始仮想アドレス
    ulong end;      // 終了仮想アドレス
    ulong flags;    // MAP_ANONYMOUS, PROT_READ|WRITE 等
    ulong used;     // スロット使用中フラグ
}
```

固定メモリテーブル（最大32エントリ）で管理。
ページフォルト時にVMA内なら物理ページを割り当ててマッピング。

## brk 設計

- Process.brk_addr: ヒープ先頭（初期値 0x800000）
- brk(new_addr): brk_addr を更新、必要に応じてページマッピング
- ヒープ上限: 64MiB (0x800000 + 64*1M)

## mmap 設計

- sys_mmap(addr=0, len, prot, flags|MAP_ANONYMOUS, fd=-1, offset=0)
- 匿名マッピングのみ対応（ファイルマッピングは v0.1.0 以降）
- VMAテーブルに登録し、ページフォルト時にDemand Pagingで確保
