# v0.0.6 設計書: シグナル・プロセス拡張

## 概要

Linux互換のシグナル基盤とプロセスライフサイクル（fork/exit/wait/kill）を実装する。

## 前提: 現在のプロセスモデル

- Process struct: pid, parent_pid, state, exit_code, context, time_slice
- 状態: TASK_RUNNING(0), TASK_READY(1), TASK_BLOCKED(2), TASK_ZOMBIE(3), TASK_STOPPED(4)
- スケジューラ: RoundRobinScheduler（最大16プロセス）
- 既存syscall: read/write/open/close/exit/getpid/uname/getcwd/chdir
- syscall_table: SYS_FORK(57), SYS_KILL(62), SYS_WAIT4(61), SYS_GETPPID(110) 定義済み・未実装

## 新規ファイル

| ファイル | 内容 |

| `include/signal.cm` | シグナル定数 (SIGKILL=9, SIGTERM=15等) |

## 実装詳細

### 1. Process struct 拡張

```
// include/scheduler.cm に追加
export struct Process {
    ...
    ulong pending_signal;  // 保留中シグナル（ビットマスク）
}
```

### 2. シグナル定数

```
// include/signal.cm
SIGHUP=1, SIGINT=2, SIGKILL=9, SIGTERM=15, SIGCHLD=17
```

### 3. sys_getppid / sys_kill / sys_wait4

- `getppid()`: current->parent_pid を返す
- `kill(pid, sig)`: 対象プロセスの pending_signal にビットセット
- `wait4(pid)`: 子プロセスがZOMBIEになるまでBLOCKED、exit_codeを取得

### 4. sys_exit 改善

- 現在の `hlt` ループからZOMBIE状態遷移に変更
- 親プロセスにSIGCHLDを送信

### 5. kill シェルコマンド

- `kill <pid>` — SIGTERMを送信
- `kill -9 <pid>` — SIGKILLを送信

## 制約事項

- fork(): 完全なアドレス空間のコピーは未実装（v0.1.0のELFローダーまで保留）
  - 代わりに `create_task(entry_fn)` でカーネルスレッド生成を提供
- execve(): ELFローダー依存のため v0.1.0 まで保留
