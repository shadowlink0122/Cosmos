# PR作成・レビュールール

## 言語
- すべて**日本語**で記述

## PRタイトル形式
```
<種類>: <簡潔な説明>

種類: feat, fix, docs, refactor, test, chore, boot, driver
```

## PR作成時
1. テンプレートに従って本文を記入
2. 関連Issueをリンク
3. チェックリストを確認
4. QEMUでの動作確認済みであること

## レビュー時
1. 設計ドキュメント (`docs/`) との整合性確認
2. ASMコードの安全性確認（レジスタ退避、スタックアライメント等）
3. テストの有無確認
4. **⚠️ ローカルパス情報の確認（重要！）**
   - `/Users/` や `/home/` 等のローカルパスが含まれていないこと
   - 確認コマンド: `grep -rn "/Users/\|/home/" docs/ .agent/ --include="*.md"`
5. 日本語でコメント

## マージ条件
- CI全パス
- 1人以上のApprove
- コンフリクトなし
