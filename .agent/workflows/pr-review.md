# PR作成・レビュールール

## 言語
- すべて**日本語**で記述

## PRタイトル形式
```
<種類>: <簡潔な説明>

種類: feat, fix, docs, refactor, test, chore
```

## PR作成時
1. テンプレートに従って本文を記入
2. 変更ファイル一覧と変更理由を記載
3. チェックリストを確認

## レビュー時の確認項目
1. **typedef/interface/impl** パターンの準拠
   - 新しい型は typedef 定義済みか
   - デバイスやサブシステムは interface 化されているか
   - impl ブロックで正しく実装されているか
2. **ドキュメント**
   - `docs/` に 00N_ ドキュメントが追加/更新されているか
   - 実装完了した設計ドキュメントは `docs/archive/` に移動されているか
   - バグがあれば BUG-00N_ ドキュメントが作成されているか
   - **注意**: `docs/` にドキュメントを置かないこと（`docs/` を使用）
3. **セキュリティ**
   - ローカルパス情報 (`/Users/`, `/home/`) が含まれていないこと
   - 確認: `grep -rn "/Users/"  .agent/ docs/ --include="*.md" --include="*.cm"`
4. **ビルド・テスト**
   - `make` でビルド成功
   - `make test` でテスト成功

## マージ条件
- テスト全パス
- typedef/interface/impl ルール準拠
- 00N_ ドキュメント更新済み（`docs/` に配置）
