# コード品質ルール

## Cmソースコード
- 4スペースインデント
- 関数名: snake_case
- 型名: PascalCase
- 定数: UPPER_SNAKE_CASE
- `//! platform: uefi` ディレクティブを全UEFIソースの先頭に記述

## コメント規約
- **設計意図**を書く（何をしているかではなく、なぜそうするか）
- ハードウェアレジスタやUEFI構造体のオフセットは必ずコメントで補足
- TODOコメント形式: `// TODO(担当者): 説明`
- 一時的なデバッグコードは残さない

## ASM規約
- `__asm__` ブロック内ではvolatileレジスタ（R10, R11, RAX, RCX, RDX, R8, R9）のみ使用
- Win64 ABI呼び出し規約に従う（UEFIターゲット）
- push/popでレジスタ配置を安全に行う
- スタックアライメント（16バイト）を維持

## ファイル構成
- 1ファイル500行目安（ベアメタルコードは簡潔に保つ）
- 関連機能は同一ディレクトリに配置
- アーキテクチャ依存コードは `arch/<アーキテクチャ>/` に分離

## 禁止事項
- マジックナンバー（定数定義またはコメントでオフセットを明示）
- UEFIグローバル変数への書き込み（ローカル変数＋ポインタ経由で受け渡す）
- 未検証のポインタ演算

## 推奨事項
- constを積極的に使用
- 構造体オフセットは計算式で表現（例: `*(st + 12)  // 12 * 8 = offset 0x60`）
- エラーチェックを省略しない（UEFI呼び出し後は必ずステータス確認）
