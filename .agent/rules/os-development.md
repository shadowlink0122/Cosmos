# Cosmos OS 開発ルール

## プロジェクトの目標と思想

### 目標
**Cm言語でゼロからOSを開発する — UEFI上で動作するモダンなOS**

### 設計思想
- 段階的モノリシック → マイクロカーネル移行
- Cmの型安全性と`no_std`環境を最大限に活用
- 理解しやすいコード（教育的価値を重視）
- 各フェーズで動作する成果物を出す

## 一貫性の原則（重要）

OS開発時は、以下の項目を**すべて一貫して**更新すること。

| 項目 | 確認事項 |
|------|----------|
| カーネル実装 | 機能が正しく動作する |
| テスト | QEMUでの動作確認 |
| docs/ | 設計ドキュメント更新 |
| README.md | 実装状況を反映 |
| VERSION | バージョン番号を更新 |

## アーキテクチャ分離

```
kernel/
├── boot/      # ブートローダ・UEFI連携
├── arch/      # アーキテクチャ依存（x86_64等）
│   └── x86_64/
├── mm/        # メモリ管理
├── sched/     # タスク管理・スケジューラ
├── drivers/   # デバイスドライバ
└── lib/       # カーネル内ユーティリティ
```

## コード品質

### ベアメタルコードの安全性
- ポインタ操作は範囲チェックを行う
- UEFIサービス呼び出し後は必ずステータスを確認
- `ExitBootServices`前後で利用可能なサービスを明確に区別する
- スタックオーバーフローに注意（カーネルスタックは有限）

### デバッグ手法
- シリアルコンソール（UART）経由でデバッグ出力
- QEMUの`-serial mon:stdio`オプション活用
- フレームバッファへの直接描画でビジュアルデバッグ

## リリース時の必須作業

1. **VERSION ファイル更新**
2. **README.md 更新** — 実装状況、実行方法
3. **QEMUでの動作確認**
4. **docs/ 更新** — 設計ドキュメント反映
5. **全テスト確認**
